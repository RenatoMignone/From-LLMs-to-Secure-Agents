# Governance

From LLMs to Secure Agents is currently maintained by Renato Mignone. The project uses a maintainer-led model while its contributor community is small.

## Roles

- **Users** read the guide, run examples, and provide feedback.
- **Contributors** submit issues, discussions, source proposals, code, or documentation changes.
- **Maintainers** review changes, manage releases, enforce project policies, and make final decisions about scope and sequencing.

Roles are earned through sustained, constructive participation. As the maintainer group grows, this document will be updated with nomination, voting, and removal procedures.

## Decisions

Small and reversible decisions are made through pull request review. Changes to project scope, learning order, evidence rules, licensing, or governance should begin in a public issue or discussion and allow reasonable time for community feedback.

Maintainers decide by seeking rough consensus and documenting the rationale. When consensus is not possible, the lead maintainer makes the final decision and records meaningful objections. Security disclosures and personal conduct reports remain private.

## Review and merge

Changes are evaluated for technical accuracy, source quality, readability, accessibility, roadmap fit, test coverage, and maintenance cost. Passing automation is required but does not replace editorial or security review.

Contributors should not merge their own pull request without another maintainer's review once multiple active maintainers exist. Urgent security fixes may use an abbreviated private review and be explained after coordinated disclosure.

## Project assets

Repository access, publishing credentials, domains, and external service accounts should use the least privilege necessary. The maintainer is responsible for preserving access continuity and removing access that is no longer needed.

## Changes to governance

Governance changes use the normal proposal and review process. The history of this file is the decision record.
